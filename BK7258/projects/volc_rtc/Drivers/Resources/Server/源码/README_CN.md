# Project_Chen 笔记本本地服务

面向第一次配置开发板的完整教程见：
`Drivers/Resources/README.md` 的"4. 接入 AI"。

这个服务运行在 Windows 笔记本上，开发板连接笔记本的
`Project_Chen` 2.4 GHz 移动热点后，访问 `192.168.137.1:8080`。

## 第一次配置

1. 在火山引擎创建 AccessKey ID 和 SecretAccessKey。
2. 打开 AI 应用 `defaultAIAgentAppName`，准备好 RTC AppKey，不要发给任何人。
3. 打开已保存的"小琴"智能体页面。
4. 双击 `configure_local_server.cmd`，按窗口提示输入密钥。
5. 配置窗口要求复制代码示例时，在小琴页面点"代码示例"，
   再点弹窗右下角"复制"，回到配置窗口按回车。

私密配置保存在 `private/`，已被 `.gitignore` 排除，不会上传 Git。

当前工程使用 AI 音视频互动应用 `6ab7750fd755df017a8abe2f` 和
`StartVoiceChat 2025-06-01`。普通 RTC 应用 `6ab770b32a0f7a03e51f0034`
不能启动"小琴"，否则会返回 `appid ... is not ai agent type`。

## 当前模型配置（2026-09-27）

- 模型：方舟内置 `doubao-seed-2-0-lite-260215`，`Mode=ArkV3`。
- 不再使用千问，没有千问备用链路；误导入千问模板时服务会报错并拒绝启动。
- 关闭深度思考，回答上限 256 tokens，保留"小琴"人设。
- ASR：豆包 1.0，流式输入流式输出（`StreamMode=0`），与最新截图一致。
- TTS：保留已能播出欢迎语的豆包双向流式合成和俏皮女声音色。
  `LLMConfig.AutoActive`、`TTSConfig.AutoActive` 都显式启用。
- 欢迎语：哟，我是小琴，你好呀？
- 开启客户端状态回调；未设置公网服务端回调地址。笔记本的私网地址不能当作
  火山云端可访问的回调地址，字幕/状态回调也不是声音的传输通道。

网页修改不会自动覆盖本地 `private/start_voice_chat_template.json`。
修改本地模板后，先关闭原服务窗口、重新运行 `start_local_server.cmd`，再重启
开发板创建新会话。旧会话不会自动切换模型。服务启动日志及 `/health` 的
`data.model` 应显示 `doubao-seed-2-0-lite-260215`。
仅调整此处云端模板无需重新编译开发板固件。

只需要更新 AI 应用 AppKey 时，双击 `set_ai_app_key.cmd`。控制台地址：

`https://console.volcengine.com/rtc/listRTC/appConfig?appId=6ab7750fd755df017a8abe2f`

## 现场演示时

1. 打开 Windows 移动热点，确认名称是 `Project_Chen`、频段是 2.4 GHz。
2. 确保笔记本自身能够上网。
3. 双击 `start_local_server.cmd`，服务窗口要一直保持打开。
4. Windows 首次询问防火墙时，只勾选"专用网络"并允许访问。
5. 开发板上电，等待 Wi-Fi 连接。安装"小琴"离线识别资源后说"小琴"；未安装时仍可用"嗨阿米诺"唤醒。

新版固件先播完本地"我在，请说"，再通知服务端请求云端欢迎语，避免两段声音
同时播放。欢迎语不再在联网进房时提前发送，因为待机中的开发板会丢弃语音。
本地提示播放期间暂停上传，播放结束后恢复持续对话。随后直接说问题即可，
不用每次重复唤醒词。"小琴"离线资源的退出词建议配置为"拜拜小琴"或"再见小琴"；旧词库继续使用"拜拜阿米诺"。

这些固件修改需要用户自行编译、烧录后才生效；仅重启服务不会更新板上的程序。
部署时先重启本地服务，再更新开发板固件。健康检查返回 `wake_protocol: 1`
代表服务支持新的 `/wakeupvoicechat` 接口。旧固件仍保留进房欢迎语行为。

排查时按顺序查看：

- `[VOICE_WAKEUP] local prompt finished`：本地提示完成，已排队请求云端欢迎语。
- 服务端"唤醒欢迎语已请求"：火山接受了播报请求，不代表喇叭实际已出声。
- `[VOICE_UPLINK]`：每 250 个编码回调打印；唤醒并连接房间后，RTC 接受帧应增长。
  待机或本地唤醒提示期间不增长是正常的。计数仅说明编码/发送流程，不能证明
  麦克风实际录到了清晰语音。
- `[VOICE_DOWNLINK]`：收到了云端音频；`write_errors` 增长表示写入播放缓冲失败。

没有日志也可能是旧固件、日志等级或串口采集问题，不应只凭这一点判断麦克风损坏。

## 服务端验证（不编译固件）

在本目录使用 Windows Python 执行：

```powershell
python test_server.py
python verify_cloud.py
```

第一条运行本地模拟测试，不调用云服务；第二条只检查配置是否能够加载。
若要实际验证云服务，可执行 `python verify_cloud.py --llm --rtc`，会产生少量
模型和 RTC 用量：创建临时测试会话，提交欢迎语和文本提问请求，并在结束时
关闭测试会话。接口接受请求不等于生成了回答；该测试不接收回复音频，也不验证
开发板的收音、播放或回声消除效果。不会调用千问接口。

服务启动后，还可以用 `python verify_cloud.py --local` 检查本机正在运行的服务
是否支持新协议，并通过它创建、唤醒、关闭一个临时云端测试会话。这同样会产生
少量 RTC/TTS 用量，不影响开发板已有房间。

当前使用方舟内置模型，不需要配置第三方模型的 `Url`、`APIKey` 或百炼地址。

应用层已支持 Wanson 返回"小琴"、"小琴小琴"、"你好小琴"时唤醒，
返回"拜拜小琴"或"再见小琴"时退出。为了避免在新资源到位前无法唤醒，
"阿米诺"旧标签仍保留为兼容入口。

但当前 Wanson 离线词库/FST 资源中并没有"小琴"，仅修改 C 代码不会改变
声学识别模型。需向 Wanson/博通集成技术支持申请与 BK7258 AIDK v2.0.1
和当前分组识别模式兼容的自定义资源。供应方可能交付新的 `libasrfst.a`、
`fst_01.h`/`fst_02.h`，或一套完整库文件；应按其交付说明替换，不要只改
`bk_wanson_asr_test.c` 中的字符串。

服务启动后，笔记本自测地址为：

`http://127.0.0.1:8080/health`

开发板使用的地址为：

`http://192.168.137.1:8080`

## 消费者桌面界面（默认入口，零依赖）

本目录已经整合为“小琴桌面服务”。普通用户只需双击
`start_local_server.cmd`，无需打开终端或手工编辑 JSON：

- **首页**：集中完成服务启停、设备状态、AI 自动配置、明文密钥授权、
  RTC/AI 应用/智能体官网跳转和开发板地址复制，无需在多个页面之间切换。
- **手动设置**：作为备用流程，表单化填写密钥，并从剪贴板导入“小琴”代码示例。
- **运行记录**：用颜色区分正常、提醒和错误信息，可一键复制给技术支持。
- **高级设置**：端口、绑定地址与原始智能体模板，默认不需要修改。

界面采用克制的 Apple 风格系统中性色和蓝色强调；所有圆角按钮使用抗锯齿玻璃渲染，包含顶部反射、柔和层次以及悬停、按下和键盘焦点反馈。
整个桌面端只依赖 Python 自带的 Tkinter，
不需要安装第三方包。`server.py` 仍负责 RTC Token 和火山 OpenAPI，界面负责
本地配置与进程管理。AI 管家需要另外填写火山方舟 API Key；默认发送脱敏配置。
用户可以明确授权 AI 在本次软件运行期间读取明文密钥，授权后每次提问会将密钥
随配置上下文发送给火山方舟模型。关闭软件或点击撤销后授权立即失效，AI 的回答
不得回显密钥，任何写配置或启停服务的操作仍需用户再次确认。

兼容入口：

- `start_gui.pyw`：打开界面但不自动启动服务。
- `start_local_server.cmd`：打开界面并自动启动服务。
- `configure_local_server.cmd`：直接打开“首次设置”。
- `set_ai_app_key.cmd`：兼容旧使用方式，同样打开“首次设置”。

关闭界面时，如果服务仍在运行，会先要求确认；确认退出后会同步停止本地服务。
旧的 `server_gui.py` 和 PowerShell 配置脚本仅保留给技术支持排障，不再作为消费者入口。

## 安全说明

- 不要将 `private/` 目录、AccessKey、SecretAccessKey、RTC AppKey 或方舟 API Key 上传到 Git。
- AI 管家的明文密钥授权仅限当前桌面会话，不会作为授权状态写入磁盘。
- 授权前界面会明确列出发送范围；未授权时嵌套在智能体模板中的密钥同样会脱敏。
- 服务仅供笔记本移动热点下的现场演示，不要直接暴露到公网。
- 智能体、ASR、TTS 和大模型仍由火山引擎/百炼提供，可能产生用量费用。
